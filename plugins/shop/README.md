# 轻量商城扩展接入

## 后台菜单、会员与商品管理

插件启用后会在后台左侧「产品」分组注册商城入口，并兼容旧版 CMS 中插件早于
侧栏菜单 API 加载的顺序。商城不强制开启会员注册：游客始终可以下单并凭订单号和
手机尾号查单；登录会员下单时会自动绑定会员账号，并在会员中心显示「我的订单」。

商城后台提供商品管理、分类管理、网站菜单和会员设置快捷入口。商品列表沿用 CMS
统一管理页；鼠标移到商品名称后可直接编辑、复制、查看、上架或下架、移至回收站，
并进入分类管理。网站导航仍由站长在「网站菜单」中决定，不在启用插件时自动改写。

角色管理会在插件启用后显示两项独立能力：「商城管理」负责售价、库存、运费与配送
范围，「订单处理」负责客户订单、收款、发货和退款。角色页同时提供「商城管理员」和
「订单处理员」预设；预设只在用户主动点击时套用，不会自动创建角色或扩大现有账号权限。

## 支付网关适配

插件内置微信支付 Native（API v3）和支付宝电脑网站支付（RSA2 证书模式）。两者都默认
关闭，只有后台开启且商户标识、私钥和全部证书校验通过后才会显示给买家。敏感材料仅保存
在 `storage/shop/payment/`，不会进入 settings 数据表；后台留空密钥或证书字段表示保留
原文件。生产启用前必须配置可从公网访问的 HTTPS 域名，并在支付平台完成对应授权。

微信支付严格校验 `Wechatpay-*` 响应/通知头、平台证书序列号与 5 分钟时间窗，再用
APIv3 密钥执行 AES-256-GCM 解密；支付宝严格校验 RSA2 签名、支付宝公钥证书序列号、
应用 ID 和卖家 ID。任一字段、签名、金额或币种不符都会拒绝推进订单。

通知地址同时支持伪静态与非伪静态模式：

```text
POST /shop/payment-notify/{gateway}
POST /plugins/shop/front/payment-notify.php?gateway={gateway}
```

`gateway` 只能包含小写字母、数字、下划线和短横线，最长 20 字符。适配器必须先按
支付平台官方规则验证原始请求正文和请求头；验签成功后返回统一结构：

```php
add_filter('shop_payment_verify', static function (
    mixed $result,
    string $gateway,
    string $rawBody,
    array $context
): mixed {
    if ($gateway !== 'your_gateway') {
        return $result;
    }

    // 这里按支付平台官方规则验签；禁止只相信正文里的 success/status 字段。
    $verified = yourGatewayVerify($rawBody, $context['headers'] ?? []);
    if (!$verified['ok']) {
        return $result;
    }

    return [
        'verified' => true,
        'status' => 'succeeded',
        'order_no' => $verified['out_trade_no'],
        'trade_no' => $verified['trade_no'],
        'amount' => $verified['amount_decimal'], // 必须是十进制字符串，不能传 float
        'currency' => 'CNY',
    ];
});
```

核心在验签后仍会独立核对订单号、订单金额和币种，并以通知摘要唯一键和
`(gateway, trade_no)` 唯一键做两层幂等。正文最大 256 KiB；失败响应只返回
`fail`，不会回显订单或数据库细节。

网关层保持平台中立，并为独立适配器保留规范标识：`alipay`、`wechat_pay`、
`stripe`、`paypal`、`wise`。其中支付宝与微信支付已内置创建支付和异步通知验签；
Stripe、PayPal、Wise 仍只是保留标识。未实现、未注册或未完整配置的平台不得显示给
访客，回调也会按未验签处理并拒绝推进订单。

## 人工收款资料与二维码

商城后台可配置最多 10 组人工收款方式，包括个人或企业收款主体、银行/收款平台、
账号、收款二维码图片和付款说明。启用的资料只在访客通过订单号与手机尾号验证订单后，
且订单仍为待付款状态时显示；订单收款确认后自动隐藏。二维码建议先上传到本站媒体库，
后台仅保存安全的站内绝对路径或 HTTP(S) 图片地址。支付平台密钥、私钥和证书不应填入
人工收款资料，未来仍由各平台独立适配器保存和使用。

## Blox 商品详情购买组件

商城启用后，商品详情模板的动态元素库会出现「商城购买」组件（元素类型
`shop/purchase`）。组件实时读取当前商品所属翻译组的销售配置，支持控制售价、库存
是否显示，以及横向/纵向布局。画布预览只输出禁用态控件，不生成可提交的购物车令牌；
商品未上架或库存不足时，画布显示提示，正式页面静默隐藏。

## 中国大陆配送与快递

结算页按「省级地区 / 市 / 区县或镇街 / 详细地址」保存中国大陆收货地址，港澳台不在
此地址范围内。商城后台可直接勾选整省不配送，也可逐行配置 `省/市/区县` 路径；规则
按路径前缀生效，例如 `海南省/三沙市` 会拦截三沙市下全部地址。结算入口和订单核心
都会重新验证，不能通过伪造 POST 绕过服务区限制。

快递公司同样在商城后台逐行维护。发货时只能从已配置列表选择，可不填物流信息以处理
自提或无需追踪的商家配送；填写物流单号时必须同时选择快递公司。

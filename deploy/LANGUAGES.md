# 多语言部署：网址前缀、语言域名与从右到左语言

YikaiCMS 的多语言站点有两种网址方式，可以混用：

| 方式 | 网址样子 | 对主机的要求 |
|---|---|---|
| 语言前缀（默认） | `example.com/en/news.html` | 只要伪静态规则正确，任何主机都行 |
| 语言域名（可选） | `en.example.com/news.html`、`example.de/news.html` | 主机要能把多个域名绑定到同一个网站目录 |

默认语言始终在主域名（后台「基本设置」里的网站地址）上，不带前缀。

后台入口：**网站资料 → 多语言设置**。语言的启用、默认语言、语言网址检查、语言域名都在这一页。

---

## 一、语言前缀

### 1.1 规则从哪来

随包的 `.htaccess`、`deploy/nginx-baota.conf`、`deploy/nginx-server.conf`、`deploy/aliyun-*` 使用**通用语言前缀规则**：

- **Apache**：网址第一段是两个字母（或 `xx-YY` 形式），并且 `lang/<代码>.php` 存在时，剥掉前缀交给对应语言。
- **nginx**：两字母开头的路径交给 `index.php`，由程序判断这一段是语言还是栏目别名。

因此以后新增语言（韩语、德语、阿拉伯语……）都**不用再改服务器规则**。没装语言包的两字母网址段，比如叫 `it` 的栏目，照常按栏目访问。

语言代码是保留别名：新建栏目或单页时不能用 `de`、`ko`、`ar` 这类代码做网址别名。

### 1.2 老站升级后要做的一步

升级**不会覆盖**站点根目录的 `.htaccess`，因为站长常在里面加自己的规则。2.0.x 及更早的站点里，语言规则写死了四种语言：

```apache
RewriteRule ^(ja|en|zh-CN|zh-TW)/(.*)$ %{ENV:YK_BASE}$2?_lang=$1 [QSA,L,DPI]
```

这条规则认不得新开的语言，`/ko/xxx.html` 会落到栏目规则上，返回 404。处理方法：

1. 打开「多语言设置」，页面上的「语言网址检查」会实际访问每种语言的 `/代码/` 网址，并标出打不开的语言。
2. **Apache**：如果认得出旧规则，会出现「一键更新 .htaccess」按钮。
   - 只替换那一条语言规则，其余内容原样保留。
   - 修改前会备份到 `storage/backups/htaccess/`。
   - 改完立刻重测，有语言打不开就自动还原。
3. **nginx**（不读 .htaccess）：把站点配置里的语言规则换成下面这段，保存后刷新页面复查：

```nginx
if (!-e $request_filename) {
    rewrite "^/[a-z]{2}(?:-[A-Z]{2})?/" /index.php last;
}
```

宝塔用户若伪静态里写的是 `include …/deploy/nginx-baota.conf;`，规则随升级自动更新，不用手改。

「站点体检」里也有「语言网址前缀」一项：旧规则挡住了已启用的语言时报「严重」。

### 1.3 兼容地址模式

服务器不支持伪静态时，站点使用 `?yk_route=…&lang=en` 形式的地址（见 [URL-COMPATIBILITY.md](./URL-COMPATIBILITY.md)）。这种模式不用路径前缀，也不支持语言域名。

## 二、语言域名（类似 WPML 的「每种语言一个域名」）

### 2.1 适用条件

- 网站地址（主域名）已在「基本设置」里填好。
- 站点使用伪静态网址（不是兼容地址模式）。
- **主机能把多个域名绑定到同一个网站目录**：
  - 宝塔：网站 → 设置 → 域名管理，添加 `en.example.com`。
  - cPanel：Aliases / Parked Domains。用 Subdomains 新建子域名时，要把它的根目录改成主站目录，cPanel 默认会另建一个目录。
  - 自己的 nginx：在站点的 `server_name` 里加上语言域名。
  - 自己的 Apache：在 `ServerAlias` 里加上语言域名。
- 每个语言域名都要有 DNS 解析和 HTTPS 证书（宝塔可以一次申请多域名证书）。
- **中国大陆主机**要求每个绑定的域名都已备案：
  - 已备案主域名下的二级域名（`en.example.com`）通常可以直接绑定；
  - 没有备案的独立域名（如 `example.de`）不能绑在大陆主机上；
  - 不确定时，以后台「检测」按钮的结果为准。

主机不支持时，继续用语言前缀就好，功能完全一样。

### 2.2 设置步骤

1. 在主机面板绑定域名、配置 DNS 和证书。
2. 「多语言设置 → 语言域名」：给要独立的语言填域名，先**不要**勾「启用语言域名」，保存。
3. 点每个域名旁的「检测」。服务器会实际访问该域名，核对回应确实来自本站同一个安装。「已连通」才算配好。
4. 勾选「启用语言域名」并保存。

启用后：
- 访问 `en.example.com` 即显示英文，网址不带 `/en/`。
- 旧的 `example.com/en/xxx` 会 301 跳转到 `en.example.com/xxx`。
- 页面里已存的 `/en/...` 链接在输出时自动改到语言域名。
- 每个域名有自己的 `sitemap.xml`，只列这个域名上的语言。
- hreflang 和 canonical 都指向各自的域名，`x-default` 指向主域名。

### 2.3 需要知道的限制

- **后台只在主域名**：在语言域名上打开 `/admin/` 会跳回主域名。登录状态按域名保存。
- **前台会员登录按域名分开**：换到另一个语言域名需要重新登录。
- **静态 HTML 直出会自动关闭**，已生成的静态文件会被清空。原因是 Web 服务器按路径直出文件，分不清访问的是哪个域名。页面缓存照常可用。
- **授权**：校验一律按主域名上报。语言域名不会被当成「另一个正式域名」，不占授权的绑定次数。
- **关闭**：取消勾选「启用语言域名」即可，填好的域名会保留，全站回到语言前缀。

「站点体检」在启用语言域名时会逐个检测这些域名，连不上、证书无效、指向别的网站，都会报「严重」。

## 三、从右到左的语言（阿拉伯语、波斯语）

阿拉伯语页面会输出 `<html lang="ar" dir="rtl">`，版式整体镜像：

- Blox 里设置的「左对齐 / 左边距」在阿拉伯语页面按「起始一侧」处理，自动换到右边。
- 表示方向的箭头图标自动翻转。
- 电话、邮箱、网址的输入框和链接保持从左到右显示。
- 字体预设里有阿拉伯文专用的几组（只用系统字体）。

内容本身要准备阿拉伯语版本，包括栏目、文章、产品和页面文字。没有翻译的界面文字会先显示英文。

自定义主题如何支持从右到左，见 [THEME-DEVELOPMENT.md](./THEME-DEVELOPMENT.md) 第 8.3 节。

## 四、繁体中文（zh-TW）

繁体中文不单独录入内容：它是简体中文站的「繁体视图」。访客打开 `/zh-TW/…` 时，页面照常按简体内容生成，
输出前整页转成台湾用字（OpenCC 词库，`includes/i18n/S2T.php`）。简体改了，繁体自动跟着变。

转换表约 1MB，2.0.4 起不随安装包，由插件市场的「繁體中文語言包」（`zh-tw`）提供：先在后台「外观与扩展 → 插件 → 插件市场」
安装它，再到语言设置启用繁体中文（缺语言包时语言设置页会提示）。2.0.4 之前安装的站点核心目录里已有一份
（`includes/i18n/s2t_maps.php`），升级不会删除，无需另装。

会被转换的：

- 页面正文与属性文字；
- 行内 `<script>` 里的文字：结构化数据（JSON-LD）、界面文案字典、灯箱标题等，`\uXXXX` 转义写法的汉字也一样；
- 前台 AJAX 返回的 JSON（如表单提交的提示）。`/api/` 开放接口不转。

不会被转换的：`<style>`、HTML 注释、带 `data-s2t="skip"` 的 `<script>`、发了 `X-S2T: skip` 响应头的响应。

访客提交回来的值是繁体，库里存的是简体，下面几处已自动对回：

- 表单的单选、多选、下拉选项（`FormFieldContract`）；
- 商城收货地区（`shopMainlandRegionFromDisplay()`）；
- 搜索关键词（`keyword` 参数先转回简体再查）。

**插件或主题开发者**：如果页面上的某段数据会原样提交回服务器，并在服务器上按简体比对，有两种做法：

1. 服务器收到时用 `S2T::canonical($value, $allowed)` 映射回简体原值；
2. 或给那段 `<script>` 加 `data-s2t="skip"`，让它保持简体。

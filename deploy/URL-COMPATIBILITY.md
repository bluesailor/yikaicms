# 无伪静态环境的 URL 兼容模式

## 给站点管理员

新安装会在安装提交前检查本站普通页面和带语言前缀的页面。两项都确认可用才选择漂亮 URL；请求失败、超时、被拦截、脚本未加载或未提供检测结果时，安装器选择动态 URL。无需手动修改服务器配置即可使用网站。

已有站点不会因一次探测失败自动改变地址，也不会在升级时重置原有模式。迁移后进入「站点设置 → URL 与链接」：

1. 点击「检测服务器支持情况」。此操作只读。
2. 点击「选择建议模式」，也可以自行选择下方模式。
3. 点击「保存设置」，阅读并确认切换影响。
4. 预览首页、栏目、详情、搜索、联系表单及多语言页面。

服务器稍后配置好伪静态后，可以再次检测并切回漂亮 URL。短暂网络故障不会触发后台自动切换。

## 地址和内容的处理边界

- 兼容地址形如 `/index.php?yk_route=page&slug=about`，不是生成静态 HTML。
- 现有 URL 助手继续生成动态链接；输出层额外转换导航、按钮和正文中可识别的 `a/area[href]`，以及 canonical/alternate 的页面链接。
- 转换复用 Dispatcher 的现有路由，不另建入站路由。保留路由身份、语言、可用查询参数和锚点。
- 不写回数据库、不修改主题源文件。切回漂亮 URL 后原始内容仍在。
- 外部域名、不同端口/协议、真实静态文件、下载链接、后台/API/插件/资源目录不接管。
- 脚本字符串、动态插入的链接、插件自定义路由及自定义表单不保证自动转换；主题开发仍应使用 `channelUrl()`、`productUrl()`、`searchUrl()` 等助手。GET 搜索表单沿用 `dynamicFormAction()` 和 `dynamicFormHiddenInputs()`，不能只把 action 改成带查询串的 URL。
- 含 `<base>` 的文档只转换明确写出本站域名的地址，避免把站外相对链接错误接管。
- 外部收藏、搜索引擎已收录的旧 `.html` 地址仍可能需要服务器重定向。服务器未把请求交给 PHP 时，CMS 无法修复该请求的 404。
- 子目录安装同样适用：探针与转换都带上站点所在目录前缀（见 [SUBDIRECTORY.md](SUBDIRECTORY.md)）。

## 检测与安全

浏览器同源请求首页、`/contact.html` 与 `/en/contact.html`（子目录站点带目录前缀），附加随机 nonce；仅 HTTP 成功、JSON 标识、nonce 和路径全部匹配才通过。每个请求最多等待 5 秒，不接受跳转；首页式软 404、旧缓存响应不会当作成功。探针只处理 GET，无数据库访问或写入，安装前可用。

服务端不接受任意探测目标，不产生外部探测请求。管理员保存仍经过权限、CSRF、枚举值和确认/旧模式校验。安装后写操作仍由原有 installed.lock 禁止。

## 开发验证

```text
php vendor/bin/phpunit --filter "RewriteCompatibility|Dispatcher"
node tests/rewrite-probe.test.cjs
php tests/smoke/rewrite_install.php
```

安装冒烟创建两个随机临时目录，以真实 HTTP 安装器验证漂亮/兼容模式、设置元数据以及安装锁；结束后清理仅由该测试创建的目录。可用 PHP 8.0 执行，需启用 pdo_sqlite。

已有站点 HTTP 冒烟使用独立样板站，不可在生产站执行：8080 运行 `tests/e2e/router.php`，8081 运行 `tests/fixtures/no-rewrite-router.php`，然后执行 `php tests/smoke/rewrite_compatibility.php`。脚本验证切换确认、过期状态拒绝、七个页面及切回行为，并恢复原模式。

本轮实测：PHP 8.0.2 / 8.2.9 的全新 SQLite 安装两种模式通过，两种 PHP 的无伪静态服务器七个页面也均通过；后台 107 页无 500、20 个核心页均为 200；浏览器完成无伪静态检测、选择/保存及模板按钮访问，并确认启用伪静态后的成功结果。全量 PHPUnit 2401 项、21704 个断言、5 项跳过；静态检查零 ERROR，双语言门禁通过。本轮新增的安装设置写入只使用参数化 UPDATE，无新表或迁移；未将 URL 安装分支单独在真实 MySQL 上重跑。
